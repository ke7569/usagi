# 简化审查建议的采用结果

已读取 `usagi-simplification-review-20260915/REVIEW.md`，并对照实盘当前源码核验。此次选择与热路径、资源冲突和恢复一致性直接相关的三项实施；不是对整份审查所有建议的完成声明。

## 已采用

### 1. 回报和报单延迟诊断移出同步写盘路径

- OMS 账户锁内只保留处理结果、逻辑时间和完成时间快照；回报诊断构造移到锁外。
- 新增多生产者、单写线程的有界诊断队列。OMS 回报 JSON 构造、编码、文件输出和 flush 都在后台执行；前台提交回报值快照。
- 报单延迟日志保留原来 backend 返回前取得的时间戳，文件编码/输出改为后台执行。ATP 原始回报日志共用支持多生产者的诊断写入方式。
- 每个诊断 sink 使用短队列锁，文件 IO 不持有该锁。沿用 CPU 64 的诊断角色，不把多生产者塞入现有 SPSC 审计队列。
- 可选 sink 在 OMS 初始化时启动，避免第一笔委托/回报才打开日志和创建线程。停止 ATP 回调后显式排空诊断任务，再卸载插件。
- 日志字段保留。队列满或写入失败显式报告并计数，可能造成诊断证据不完整，不改变已经报出的委托结果。OMS 权威 journal 的发送前持久化逻辑未改动。

同机、相同 CPU 和相同 1,000 条已受理订单回报，使用真实 OMS Engine 和模拟 backend，写入真实普通文件：

| 版本 | report() 平均 | P50 | P99 |
|---|---:|---:|---:|
| 原同步诊断 | 124.123μs | 124.521μs | 134.491μs |
| 最终快照＋后台构造 | 4.985μs | 4.560μs | 8.830μs |

两版各 2,000 条诊断记录，在去掉测量时间戳/时长字段后逐条相同；所有回报成功处理，账户 ready。此结果是回报处理局部基准，不是预测或完整实盘延迟。

第一版只后台 dump/写文件、前台仍构造 JSON，虽然均值改善到约 78μs，但 P99 回退到约 510μs；已被最终快照方案替代，不将第一版作为部署结果。

并发测试：4 个生产者各 200 条、每条 4KiB，故意暂不读取管道使后台文件 IO 阻塞，生产者仍能完成入队。显式 drain 和析构后 800 条全部读回，每个生产者顺序正确；另覆盖关闭日志及 `/dev/full` 写失败。

### 2. IRQ 调优与检查使用同一份运行角色推导

`sse_receive_ops.py` 不再依赖过时的 `PROTECTED=8..47`，而从 capture 启动模板、交易配置和有效 systemd 环境读取实际 receive/dispatch/journal、预测主线程、全部 worker、TD、审计和诊断 CPU。调优与启动检查复用同一个策略函数。

保护集合包含 CPU 136 和 144..248 的实际 worker。行情 IRQ 分配到原域内排除应用角色后的 65–95，避开诊断 CPU 64。其他可修改 PCI-MSI IRQ 只分配到保护集合和行情 IRQ 域以外；已删除可能重新落到预测核的旧回退公式。

当前实际限制：34 个 megasas RAID 控制器 IRQ 的亲和性写入被内核拒绝，一些与应用核重叠。没有把它们报告成已隔离。每次启动调优会重新尝试并记录 boot ID、IRQ 名、允许集合及写入错误；运行检查只认可本次 boot 内完全匹配的拒绝记录，并显式返回重叠。新的、未记录的可修改 IRQ 冲突仍使检查失败。

已执行夜间调优，行情 IRQ 新分配生效；调优仍会在发现 capture 运行时拒绝修改。5 项策略测试覆盖角色保护、回退不落预测核、行情 IRQ 避开诊断核、配置变化和未知冲突不被静默放行。

此次统一的是角色推导和检查规则，并未把全部 systemd/drop-in 重写成一个新的资源管理框架。

### 3. 恢复实现收敛及回归入口补齐

- `common/recovery/SZERecoverable.cpp` 改为包含公共头文件。
- 沪深 CMake 使用公共实现路径；旧深圳头文件和 standalone cpp 编译入口保留为很薄的兼容转发。保留 `sze_recovery` 命名空间、API、磁盘格式与 SHM 格式。
- 注册并发诊断测试和 CPU 策略测试到 CTest。
- v0.6 golden 测试支持显式 `T0_V06_GOLDEN_DIR`；本次构建配置了现有 fixture 并实际执行，未在远端安装 Python 3。

9 项定向 CTest 覆盖并发诊断、CPU 策略、OMS、OMS 恢复、journal core/handoff、v0.6 策略、SSE session 和 golden 模型。旧深圳入口另外编译并通过恢复测试。

额外一次将并发恢复测试限制在单 CPU 时，旧测试对中间 `handoff` 状态的时序断言失败；允许两个 CPU 后通过。没有修改恢复行为来迎合测试，也不把单 CPU 那次报告为成功。
