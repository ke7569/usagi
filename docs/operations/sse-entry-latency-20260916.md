## 实现

1. **CRC按8字节分组查表计算。** 保持IEEE CRC32多项式、初值、末尾异或及文件格式不变。capture和预测端一起更新，兼容旧capture和历史文件。独立测试1224字节负载的中位耗时从3.884µs降到1.952µs，8192字节从25.870µs降到12.941µs；校验值一致。
2. **股票完成即可交付。** 输入BatchEnd仍先于因子和预测；固定worker按FIFO处理此前订单簿更新。worker完成一个股票的结果后，以release/acquire发布，输入owner可以取走该结果，无需等待同worker后续股票、其他worker或全局队首任务完成。
3. **保持数据所有权。** Close开始前按候选数预留输出空间，发布后不会扩容；owner只读取已发布的元素，任务全部完成和结果消费后才能复用槽位。快照依旧遵循本worker顺序。汇总BatchEnd只承担完整批次计数，不再阻塞已经越过输入闭批边界的信号。
4. **整合此前stage2候选。** 实盘策略线程自行推进OMS/TD及撤单时钟，不再每条行情投递clock控制消息；已闭批结果直接进入v0.6策略，绕过策略端二次组批。账户决策、资金占用及报单仍由单个策略线程串行执行。
5. **只轮询有结果任务的worker。** 避免每条输入反复读取全部worker的完成状态，减少本轮改造引入的额外轮询开销。

跨股票交付不再按股票代码排序，未来资金竞争时的先后顺序可能不同；同股票事件与预测顺序、采样规则、模型状态和静态仓位逻辑保留。旧策略与串行入口继续存在。

新路径可能在整个worker任务结束前交付本股票，因此不能再用“worker_done → delivery”表示等待时间；本报告改用“本股票模型结束 → delivery”。

## 验证

- 新旧均恢复23,819,663条历史输入，再处理下午前缀及测量窗口，累计7,496,541次预测、16,117,163条输出样本。2318只股票的有序输出摘要一致，覆盖输出类型、逐笔/快照序号、因子值、预测有效性、选择标志及四头预测值。
- paper的10笔报单、10笔撤单除monotonic时间戳外字段与顺序一致。
- 16项定向回归通过，另有4017行模型golden通过。回归覆盖CRC兼容性、journal/SHM恢复、capture启动及重启、订单/撤单、旧策略和运行门控。
- 人为卡住一个worker时，确认其已发布的首只股票、另一worker以及另一worker后续批次可以继续交付；同一worker尚未计算的股票不会被提前交付，汇总BatchEnd不会提前生成。输入尚未闭批时不输出预测。
- 覆盖输出槽和交付队列反复绕回、数据所有权、策略消费者错误传播、无行情时撤单定时器推进，以及直接进入策略后的订单字段/资金占用/撤单截止时间一致性。
- 启动器首次测试因测试进程CPU范围过窄，自动L3分配拒绝启动；使用正常可用CPU范围后，正常重启、异常重启及历史保留检查通过。
- 最初的基线回放工具混用了新旧内部ABI头文件，在初始化阶段失败，其结果全部弃用。最终基线使用完整旧头文件覆盖及匹配的冻结库，候选使用本轮完整构建，避免混用内部接口版本。
