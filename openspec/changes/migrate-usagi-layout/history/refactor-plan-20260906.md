日期: 2026-09-06。状态: 首个配置层交付已实现，见 [统一配置工具](unified_config.md)。完整运行时重构、replay/live 共用链路、国君接入及部署尚未完成；原 S1 的完整模型/回放/SDK 基线仍有待验证项。

当前增量已推进两市独立行情处理目标、公共 capture/replay 和可选/必需录制策略，见[行情层说明](market_data_stream.md)及 `openspec/changes/unify-market-stream-runtime/tasks.md`。这里的“推进到第四步”是当前讨论批次的目标，不等同于本文件原七阶段中的 S4 全部完成。旧沪市插件接线、深市 journal/SHM 实时恢复衔接、完整交易运行时和生产模型全天验收仍单列，不以独立工具通过替代。

## 1. 目标与执行原则

一个仓库，沪深独立的市场流水线，分别选择 MD、TD、账户及策略配置；共用语义一致的策略、订单状态管理和因子函数。部署实例按账户和市场隔离，分别构建、运行、发布和回退。

- 保留各市场既有参数和行为差异。深市最新仓位规则不因共享代码而自动应用到沪市。
- 修复已确认的问题与纯结构重构分别提交。前者记录预期行为变化，后者以固定输入的前后对照验收。
- 继续使用 Deepwin 的插件和现有调用路径；公共核心不依赖 SDK、`WCStrategyUtil` 或 `LF_*`。不为抽象接口额外增加网络服务、消息中间件或线程队列。
- 实现按协议复用，实例按券商和账户配置。相同协议可以共用适配器，不同协议分别实现；MD 与 TD 独立选择，部署时检查组合是否兼容。
- 同一阶段的小任务可分别提交；每个提交可检查、可回退。先完成一条真实调用链，再扩大到另一市场。
- 离线 replay 与 live 必须共用同一构建中的解码、订单簿、采样、因子、模型和策略实现，仅替换输入、时钟及执行 driver。记录接收时间和批次边界，通过虚拟时钟复现定时行为；缺这些信息的 CSV 只能作有限分析。

### 3.2 新增位置与依赖方向

`src/t0-core/contracts/` 放身份、时间、行情/信号和执行契约；`strategy/` 放决策与规则；`execution/` 放账户及订单状态；`factors/` 放已验证的通用计算；`tests/` 放相应测试。这些是计划路径，按任务需要逐个创建。

SDK 转换保留在 `modules/deepwin_guoxin/`，国君资料明确后新增 `modules/deepwin_guojun/`。沪深专属模型和因子先保留现有路径，市场运行时可分别提取为 `src/t0-main/strategy/SzeRuntime.*` 和 `sse-t0/strategy/SseRuntime.*`。不先做全仓目录搬迁。

依赖方向为“入口/市场/适配器 -> 公共核心”。公共核心不反向包含市场运行时、Deepwin 或券商头文件，市场运行时之间不互相链接模型实现。普通调用、直连和离线执行器都服从同一执行契约。

### 3.3 S1 要先固定的契约

- 身份: 明确 market、feed instance、gateway instance、account、strategy instance；内部订单 ID 唯一，映射到具有账户及会话作用域的券商订单 ID；撤单和回报始终归原通道。
- 时间与数据: 区分 exchange、realtime、monotonic 及其单位；保留沪深事件差异、频道连续性和有效性。同一信号的盘口、预测、样本 ID 对应同次采样，跨线程数据生命周期明确。
- 执行: 分清发送结果、受理、成交、撤单结果与未知状态；统一累计量/增量、重复/乱序回报和查询完成语义。发送结果不确定时先对账，不自动重发。
- 能力: 适配器声明订单类型、字段完整度、查询/恢复和限速约束；按市场、通道、账户权限的交集检查策略需求。“限价 + 延迟撤单”与原生 FAK 分别表达，不静默互换。
- 状态: 模型、因子、订单和门禁按实例隔离；资金/额度以实际账户为边界。同账户跨市场先明确预算分配或账户级统一控制；实例恢复不隐式撤销其他实例的订单。

## 6. 节省 Token 的协作规则

### 6.1 任务选择与升级

- 主代理承担架构、契约、语义冲突、回报状态机、账户资金、并发/时间/恢复、数值一致性及最终整合审查。已知问题的修复也按风险分配，不因描述短就交给小模型。
- Luna 承担路径/来源清点、明确清单的搬迁、既定类型和字段接线、已给输入/预期输出的测试、配置转换、文档和构建脚本。测试场景与关键预期由主代理确定，避免只是复刻实现。
- 默认使用 `gpt-5.6-luna`，简单任务使用低推理档位；如果不可用，说明实际使用的替代模型，不声称已经切换或保证固定节省比例。
- 只在任务能独立推进时委派。能由一次命令完成的工作直接执行；多个同目录小任务可合成一次有界委派，避免启动和上下文成本超过收益。
- Luna 遇到契约不清、必须越过文件范围、ABI/线程/数值变化时提交简短证据给主代理。一次针对性修正仍无法解决就升级，不多轮猜测或重复扫描全仓。

### 6.2 最小任务包

后续委派默认不继承完整对话，只提供以下模板。主代理发送前填写准确路径和批准的规则，避免子代理自己重新设计方案。

```text
任务 ID: Sx-y
工作区/基线: <绝对路径 + commit 或源码校验值>
目标: <一个可验收结果>
前置决策: <已批准的接口/映射/预期行为，引用本文具体阶段>
只读输入: <通常 2-5 个文件及必要函数范围>
允许修改: <明确文件列表，通常 1-3 个文件>
验收: <指定命令、输入与预期；关键失败/边界场景>
遇到边界: <不明语义、越界依赖、ABI/并发/数值变化时报告>
返回: 修改文件、结果、测试摘要/日志路径、剩余问题；通常不超过 12 行
```

不把完整 review、SDK、Boost/Eigen、生成配置或全天日志复制到任务上下文。日志保留到文件，只返回结论和首个相关失败；失败后由主代理决定下一次需要读取的范围。当前代码中的用户修改同样必须保留。

### 6.3 并发、检查与持久状态

- 共享工作区时，每个写入文件只有一个负责人。`StrategyBase.*`、`ZStrategy.*`、根 CMake 的语义修改由主代理串行处理；只有明确移交所有权后，Luna 才进行其中的机械编辑。
- 开发机支持 worktree 时使用独立工作区；本机 Git 1.8.3.1 不支持 worktree，实施时使用独立 checkout/副本。按具体提交整合，不覆盖原工作区的未提交内容。
- 每个任务先跑必要的局部验证，主代理审查差异和证据；阶段末再跑相关集成验证。相同代码/依赖/配置下已经通过的检查不反复全量运行，只有变更影响、失败或未决问题才扩大范围。
- 数值对照使用同一模型、配置、数据及构建参数；性能比较使用同机同条件的基线，记录 p50/p99/最大延迟和分配开销，不能把模型或编译优化混进纯抽取任务。
- 本文保存稳定方案。S1 开始后用一份简短执行记录保存任务 ID、基线、完成提交、检查及下一步；不反复改写整份设计，也不为每次委派复制一套设计文档。

## 8. 后续项目命名与目录迁移

用户希望将项目从 `sze-t0` 更名为 `usagi`，以公共模块和沪深独立目录表达单仓库结构。本阶段为后续计划，排在当前策略入口接线、保护逻辑、离线端到端验证和深市 `.szej`/SHM 恢复衔接完成之后，单独建立机械迁移变更。本次不移动目录、不修改仓库 remote 或项目元数据，也不自动 commit、push 或部署。

目标骨架如下，子目录命名和文件归属在实际迁移前逐项审查确定：

```text
usagi/
  common/  已确认共用的契约、运行基础、策略和执行模块
  sze/     深市行情、订单簿、采样、因子、模型与入口
  sse/     沪市行情、订单簿、采样、因子、模型与入口
```

仅将已经确认语义共用的代码归入 `common/`，不为目录整齐提前扩大抽象范围。市场、券商协议、账户实例继续独立：券商适配实现及其 SDK 依赖按实际协议归属确定，不能因移动到公共目录就变成全目标必需依赖。模型、scaler、静态数据和录制资产保留各自市场、版本、来源哈希和部署归属，不混用或重复生成。

实施顺序：

1. 固定迁移前代码和两市相同的模型、配置、静态数据及回放 fixture，列出逐文件旧路径到新路径的映射。清点被 Git 忽略的模型/依赖目录、外部运行目录和仍被使用的绝对路径，保留已有用户改动及历史来源记录。
2. 按映射迁移源码并更新 include、CMake 源列表和依赖边界，再更新配置生成、部署打包、启动脚本、测试 fixture 路径及文档引用。明确源码路径与运行路径的区别；旧配置键、插件名称、服务入口和运行目录需要保留兼容时，使用列明范围的兼容入口，并记录后续退出条件。
3. 项目名称改为 `usagi`，不更改交易所语义。`SH/SZ`、协议类型、证券代码、market/source ID、订单路由和账户标识按原契约保留，禁止对 `sze`、`sse` 或路径片段做全仓无差别替换。仓库托管名称、remote 和实际部署路径另行列出具体操作及兼容影响后处理。
4. 使用迁移前同一组固定 fixture，验证两市独立构建和相应离线端到端路径。样本、因子、预测、订单意图、回报状态及恢复行为应与迁移前一致；数值容差沿用已经确定的基线。检查未意外链接另一市场模型或无关券商 SDK，并核对打包内容和运行路径。
5. 形成独立可审查的迁移结果及未来部署/回退方案，保留原部署包、配置和模型资产的对应关系。实际发布前完成兼容验证，允许逐市场、逐账户回退；目录迁移本身不触发实盘切换、订单操作或自动推送。

完成标准是名称和目录反映已经建立的模块归属，原有两市行为及独立发布能力保持可验证。前文路径仍作为实施历史和审查定位保留；实际迁移完成后追加映射结果，不回写成历史代码曾位于新目录。
